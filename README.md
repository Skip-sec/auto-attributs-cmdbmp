# MaxPatrol VM & Jira Insight CMDB Synchronization Tool 

Автоматизированный инструмент для двусторонней интеграции и обогащения данных между **Jira Insight CMDB** и **Positive Technologies MaxPatrol VM**.

### 🚀 Основные возможности
1. **Сбор активов из MaxPatrol VM**: Скрипт выгружает текущую матрицу хостов (включая FQDN, IP, тип ОС) по гибкому PDQL-запросу.
2. **Обогащение из Jira Insight**: На основе короткого имени хоста утилита опрашивает CMDB Jira, извлекает кастомные атрибуты с учетом приоритетов типов объектов (например, Virtual Server -> VDI -> Global). 
3. **Поддержка множественных ИТ-систем**: Если хост в Jira Insight привязан к нескольким ИТ-системам, утилита собирает их все и объединяет в одну строку через стандартный разделитель — точку с запятой `;`.
4. **Импорт дополнительных атрибутов**: Сформированный UTF-8-BOM CSV-пакет автоматически загружается обратно в MaxPatrol VM для заполнения текстовых полей `UF_` в соответствии со схемой `UserModel.xml`.
5. **Автоматический Group Management**: Скрипт на лету парсит строки с ИТ-системами, разделяет их по `;`, собирает полный срез уникальных систем и Владельцев, после чего автоматически генерирует для них **динамические группы активов в MaxPatrol** с использованием предикатов на базе оператора `like` (с защитой от создания дубликатов).

## 🛠 Маппинг атрибутов
Инструмент извлекает данные из внутренних ID схем Jira Insight и транслирует их в пользовательские атрибуты MaxPatrol VM:

| Атрибут MaxPatrol VM (UserModel.xml) | Описание поля | Тип данных в Jira | ID в Jira Insight | Особенности заполнения |
| :--- | :--- | :--- | :--- | :--- |
| **`UF_cmdbitsystem`** | Информационная система | Reference Object (Множественный) | `2288` | Записывается строкой через `;` (например, `SYS1;SYS2`) |
| **`UF_cmdbresponsible`** | Ответственный за хост | Reference Object | `186` | Одиночное значение |
| **`UF_cmdbstatuslive`** | Статус жизненного цикла | Status Object | `238` | Одиночное значение |
| **`UF_cmdbowner`** | Владелец актива | Reference Object | `2282` | Одиночное значение |
| **`UF_cmdbupdategroup`** | Группа обновлений ОС | Select (List) | `2302` | Одиночное значение |
| **`UF_cmdbsecurityupdates`** | Режим обновлений ИБ | Select (List) | `2338` | Одиночное значение |

*(Примечание: Внутренние ID в вашей инсталляции Jira могут отличаться, коды выше приведены как пример).*

## ⚙️ Настройка и развертывание

### 1. Требования к среде
* **Python 3.8+** 
* Доступ от сервера автоматизации до API MaxPatrol VM (порты `3334`, `443`) и до Jira API (`443`).

### 2. Подготовка окружения
Клонируйте репозиторий и создайте файл переменных окружения `.env` на основе примера:
```
cp .env.example .env 
``` 
Заполните конфигурационные параметры в `.env`:
```
# MaxPatrol VM Credentials 
MPVM_USER=your_api_username 
MPVM_PASSWORD=your_api_password 
MPVM_CLIENT_SECRET=your_mpx_client_secret 

# Infrastructure IDs 
MPVM_SCOPE_ID=реальный_uuid_инфраструктуры
MPVM_ROOT_GROUP_ID=uuid_корневой_группы_импорта

# Папки для автоматических динамических групп (брать из URL веб-интерфейса MP VM: параметр groupId)
MPVM_IT_SYSTEMS_ROOT_ID=uuid_папки_для_групп_ит_систем
MPVM_OWNERS_ROOT_ID=uuid_папки_для_групп_владельцев

# Jira Insight Configuration 
JIRA_URL=https://your-jira-domain.com 
JIRA_BEARER_TOKEN=your_personal_bearer_token 
``` 

### 3. Установка зависимостей
```
python3 -m venv venv 
source venv/bin/activate 
pip install -r requirements.txt 
```

## 🚀 Запуск скрипта

Для разового запуска скрипта в ручном режиме (без активации venv) выполните команду из корня проекта:
```
./venv/bin/python3 main.py 
``` 

### Настройка автоматизации (Cron)
Для регулярной синхронизации (например, каждые 4 часа) добавьте задачу в `crontab` сервисного пользователя автоматизации (`isd-automation`):
```
0 */4 * * * cd /opt/auto-attributs-cmdbmp && ./venv/bin/python3 main.py >> logs/sync.log 2>&1 
```

## 🔄 Логика автоматического управления группами

При обработке активов модуль `group_manager.py` выполняет следующие действия:
1. Собирает срез уникальных значений полей `itsystem` и `owner` со всех успешно обработанных хостов. Если в поле `itsystem` обнаружен разделитель `;`, строка дробится, и каждая ИТ-система учитывается независимо.
2. Выполняет проверочный запрос `GET /api/assets_processing/v2/groups?parentId=...`, чтобы узнать, какие группы уже существуют в целевых папках, предотвращая создание дубликатов.
3. Если группа отсутствует, отправляет `POST`-запрос на создание динамической группы со следующим предикатом:
   * **Для ИТ-систем (с учетом множественности)**: `host.UF_cmdbitsystem like '%ИМЯ_СИСТЕМЫ%'`
   * **Для Владельцев**: `host.UF_cmdbowner = 'ИМЯ_ВЛАДЕЛЬЦА'`
4. Группы мгновенно начинают наполняться хостами на стороне MaxPatrol VM. Благодаря оператору `like`, хост со значением `SYS1;SYS2` одновременно и корректно попадет как в динамическую группу `SYS1`, так и в группу `SYS2`.

## 🛠 CI/CD Пайплайн (GitLab CI) 
Проект поддерживает автоматический деплой на сервер автоматизации (`srv-isd-auto.net.billing.ru`) при пуше в ветку `master`. Пайплайн использует `rsync` для атомарного обновления файлов проекта от имени сервисного пользователя.
* Права на целевые папки изолированы под пользователя автоматизации.
* Переменная `.env` добавлена в `.gitignore` и исключена из синхронизации для обеспечения безопасности данных.
